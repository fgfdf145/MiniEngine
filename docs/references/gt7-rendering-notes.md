## 1. 总原则（PBS 2025）

- **物理值进，感知出。** 光照和材质全部用实测物理量（光谱测量换算的 RGB、HDR 摄影测得的车灯、
  ASTM G-173 太阳光谱驱动的大气），"看起来不对就修管线，不调资产"。
- **色调映射是 PBR 管线的一部分**，不是后期美化。用户看到的是 渲染 → 色调映射(+OETF) → 显示器
  → 人眼 的结果，所以色调映射、眩光、自动曝光、自动白平衡被当成一个整体（"Physically Based Tone
  Mapping"）设计，彼此有显式联动。
- **全游戏只有一套参数。** 曝光和白平衡完全由模型决定，不再按场景手调。

### 1.1 真实世界亮度参考（cd/m²，原文现场实测）

| 场景 | 亮度 |
| --- | --- |
| 太阳 | ≥ 1e8 |
| 阳光下云顶后向散射 | 34 000 |
| 阳光下冰川 | 16 000 |
| 晴空 | 2 800–5 000 |
| 阴天傍晚天空 | 3 800 |
| 铺装路面（阴天） | 660–800 |
| 隧道 LED 灯（直视） | 20 000 |
| 路灯（直视） / 红色信号灯 | 3 000 / 3 100 |
| 应急出口标志 | 130 |
| 夜间人行道 | 0.6 |
| 夜空 | 0.02 |

可作为本引擎场景与测试的量级基准。自然场景里除太阳外，只有阳光直射的云和雪能超过 10 000 nit。

### 1.2 感知模型

- 人眼同时动态范围约 3.7 log 单位（约 5 000:1），更大的范围靠适应获得。
- **对比度恒常只在约 2–200 nit 成立**（Weber 区）。更暗时受 de Vries–Rose 律限制，更亮时感受器
  漂白饱和，两端响应都是非线性的。sRGB 显示器的亮度范围正好落在恒常区。
- 因此**曝光 ≠ 适应**：曝光是线性缩放，而人眼在高亮区压缩对比度、在暗区被内部噪声淹没。
  色调映射曲线的 **shoulder 就是高亮端的感知压缩，toe 就是暗端的内部噪声**；S 形曲线是感知上的
  必然，而不只是胶片遗产。
- 试验结论（GT Sport 之前）：**中间调线性对真实感至关重要**；高低两端要 S 形；曝光正确时，超色域
  带来的颜色裁切问题不大。

## 2. GT7 色调映射算子（PBS 2025）

### 2.1 GT Tone Mapping 曲线（GT Sport 起，V2 保证收敛）

三段：toe（`midPoint * (x / midPoint)^toeStrength`）与线性段用 smoothstep 混合，到
`linearSection * peak` 之后切换为指数 shoulder `kA + kB * exp(kC * x)`，渐近到 peak。
V2 相对原版的改动是 shoulder 严格收敛到峰值亮度（原版输出范围不封闭）。

GT7 使用的参数：`alpha = 0.25, midPoint = 0.538, linearSection = 0.444, toeStrength = 1.280`。

### 2.2 GT7 的四步

1. 逐通道过曲线，得到带色相扭曲的 "skewed" RGB。
2. 原始 RGB 与 skewed RGB 都转到均匀色彩空间（UCS；默认 ICtCp，可选 Jzazbz）。
3. 构造 "untwisted" 颜色：亮度取 skewed 的 I，色度取原始的 Ct/Cp，并乘以
   `1 - smoothstep(0.98, 1.16, I / I_peak)`，接近峰值时向白色褪色。
4. 在线性 Rec.2020 RGB 中混合：`lerp(skewed, untwisted, 0.6)`，再裁到峰值。
   作者试过在 UCS 里混合，RGB 混合效果更好。

效果：中间调无色相扭曲（刹车灯保持红色、橙色车漆不偏粉），高光保留少量"相机感"扭曲，
饱和蓝天在 +2 EV 下仍有亮度层次。

### 2.3 单位约定（与本引擎直接相关）

- **帧缓冲 1.0 = 100 cd/m²**（`REFERENCE_LUMINANCE`）。算子的输入已经是曝光后的值。
- **SDR 纸白 = 250 cd/m²**。SDR 按 250 nit 峰值做映射，再乘 `1 / 2.5` 回到 sRGB 的 1.0 = 100 nit。
- HDR 输出：`initializeAsHDR(peakNits)`，峰值范围 250–10 000 nit，输出 `[0, peak]` 帧缓冲单位，
  之后接 PQ inverse-EOTF。同一条曲线随峰值自动变形，SDR 与 HDR 观感一致。
- 显示器峰值差异很大（原文举例 357 到 5 436 nit），所以曲线必须能按峰值参数化。

### 2.4 性能：3D LUT

GT7 把算子烘焙成 3D LUT，索引前做 `pow(x, 1/4)` 的非线性（即按 x⁴ 采样）。32³ 非线性表的色带
比 64³ 线性表还少。

### 2.5 常见算子对比（原文结论，中立陈述）

| 算子 | 类型 | 可变 HDR 峰值 | 调参 |
| --- | --- | --- | --- |
| Reinhard | 逐通道 | 否 | 易 |
| Hable Filmic | 逐通道 | 否 | 难 |
| AMD VDR | 逐通道 | 是 | 难 |
| AgX | 色彩体积 | 否（事实标准是固定 LUT） | 固定 |
| Khronos PBR Neutral | 色彩体积 | 否 | 固定 |
| ACES 1.3 / 2.0 | 色彩体积 | 需额外 ODT / Output Transform | 需额外工作 |
| GT | 逐通道 | 是 | 易 |
| GT7 | 色彩体积 | 是 | 易 |

注意：ACES 把 0.18 映射到 10–15 nit，其它算子约 18 nit，所以 ACES 画面普遍偏暗约 1.8 倍。

## 3. 眩光（PBS 2025）

- 定位：饱和像素本身不再携带信息，眩光把能量向外扩散，**在空间域扩展色调映射的感知输出范围**
  （七个同样饱和的像素加上眩光后能看出亮度差别）。
- 物理模型：**Fraunhofer 衍射**，PSF 依赖光圈大小、形状和波长，按波长积分，每个 F 值一套。
  **F 值由曝光决定**，所以亮场景眩光明显、暗场景收敛，无需按场景手调。
- HDR 输出时把峰值亮度差当作 F 值差，**HDR 上的眩光比 SDR 更窄**（高峰值显示器不需要那么多感知夸张）。
- 实现很常规：提取高亮 → 反复高斯模糊并降采样得到各频段 → 按权重合成逼近衍射 PSF，带少量色散。
  10 个 F 值 × 24 个权重，由作者手工对齐物理真值。
- 景深与运动模糊同样是物理的、HDR 兼容的。

## 4. 自动曝光与自动白平衡（PBS 2025）

### 4.1 需求量级

- 昼夜约 16 EV；天气约 6 EV；局部环境（隧道、林荫、车内）最多约 10 EV，且车速快、响应要快。
- 回放每 4–5 秒切一次机位，机位之间没有连续性。
- 环境变化是信息（"天要黑了""暴风雨要来了"），**自动曝光不应把它抹平**：夜晚应该保持暗，
  雪地和沙滩应该保持刺眼。

### 4.2 双层适应

| 层 | 模拟对象 | 范围 | 速度 |
| --- | --- | --- | --- |
| 短期 | 瞳孔 + 神经增益 | 3–5 EV | 数秒 |
| 长期 | 感受器灵敏度 | 约 12 EV | 数十分钟 |

长期适应给短期适应设上下限。白天短期适应想继续变暗，但被长期上限挡住，画面保持轻微刺眼；傍晚
短期适应完全展开；深夜仍被长期下限挡住，保持暗。明适应快于暗适应，加上白平衡不同，所以同一太阳
高度下黎明和黄昏的观感不对称。

### 4.3 多参考测光

只用帧缓冲直方图不稳定（只覆盖视锥）。GT7 用五个参考、固定权重混合，曝光和白平衡各一套权重：

| 参考 | 空间范围 | 角度范围 | 取值 |
| --- | --- | --- | --- |
| 帧缓冲 | 视点局部 | 视锥内 | 直方图均值 |
| 光照探针 | 位置局部 | 全球面 | 积分 |
| 天空穹顶 | 与位置无关 | 半球 | 积分 |
| 太阳光 | 与位置无关 | 单方向 | 照度 |
| 天空可见度 | 位置局部 | 半球（SH） | 积分，来自基于 SH 的 AO |

### 4.4 自动白平衡

与自动曝光同一套机制，但控制色温和色差（delta），缓慢适应到 D65。测量结果转到 Yxy，按亮度加权
混合，再与理想光源混合；夜间加一个微弱的虚拟光源稳定测量；适应范围参照真实相机 AWB 规格。

## 5. 光追镜面 GI（S2023）

- GT7 是**前向渲染器**（复杂车漆、路面、草地着色器，4K 全分辨率），Disney BRDF + 预积分 IBL。
  光追只在非比赛模式（照片、展厅）启用，不为光追单独做资产。
- **保留 split-sum**，只把预滤波 cubemap 的那一项换成光追：
  - 光栅 pass 输出直接光 + 漫反射 GI（不含镜面 IBL），外加薄 G-buffer：法线、粗糙度、预积分镜面系数。
  - 半分辨率（1920×1080），每像素每帧 1 条光线，蓝噪声 + GGX 重要性采样方向。
  - 命中点用与光栅相同的着色函数求辐亮度，**不递归**（GI 已在着色中近似，高阶误差不显眼）。
  - 输出颜色（YCoCg）、反射方向、命中距离、1/pdf。
  - 去噪三步：SSSR 式样本复用（Stachowiak 2015）→ 时间滤波（history）→ 联合双边滤波（亮度、法线、深度）。
  - 之后在低分辨率缓冲上**单独再做一次 TAA**，边缘稳定性大幅改善。
  - 按深度双边上采样，乘以镜面强度缓冲，叠加回光栅结果。

## 6. 天空（S2023）

- **离线**：基于实测的大气模型。Rayleigh 的现有近似（解析相函数、指数密度）已足够准确；
  **Mie 不够**：真实气溶胶粒径是双峰分布（细模态 + 粗模态），相函数要由实测分布数值推导，
  垂直密度剖面也不是指数分布，而且可以按高度分层。
- **实时**：离线结果烘焙成 LUT。
  - 每种天气一张 LUT：64 层的 2D 纹理数组，每层对应一个太阳高度，128×32。
  - 球面参数化：经纬度 → 水平归一化 → v 方向非线性自适应映射，太阳附近和地平线附近纹素最密。
  - "基底天空"：晴天两张（clear、hazed，按 haziness 线性插值）加阴雨六张（cloudy0–5，按 cloudiness
    插值，高空云形成时散射变化快，所以多放几张），共 8 张 3D LUT。
- 细节见 GDC 2023 *Realistic Real-time Sky Dome Rendering in Gran Turismo 7*。

## 8. 与 MiniEngine 的对照

### 已有

| 项 | 本引擎现状 | 与 GT7 的关系 |
| --- | --- | --- |
| 色调映射 | `shaders/vulkan/gt7_tonemap.glsl`：GT7 参考实现的 SDR + ICtCp 移植，与 `tests/third_party/gt7/` 下的参考逐位一致 | 同一算子；尚无 HDR 输出，无 3D LUT |
| 单位 | 物理单位渲染；`ExposureFromEv100` 让曝光后 1.0 = 传感器饱和；`kExposedToGt7FrameBuffer = 2.5` 把它放到 250 nit 纸白 | GT7 帧缓冲 1.0 = 100 nit，纸白 250 nit，换算一致 |
| 自动曝光 | 帧缓冲直方图，百分位裁剪，明暗不对称的指数适应，EV 钳制 | 相当于 GT7 的单层"短期适应"加单一参考 |
| 眩光 | Jimenez 2014 bloom，无阈值，固定 4% 能量混合 | 同属多级高斯近似；GT7 的权重随 F 值（即曝光）变化 |
| 天空 | Hillaire 2020 的四张 LUT，解析 Rayleigh / Mie | GT7 用实测 Mie 双峰相函数、离线烘焙 |
| 镜面 GI | split-sum 预滤波 IBL | GT7 光追方案同样保留 split-sum，只替换 cubemap 项 |

### 对预曝光 HDR 缓冲的启示

1. **GT7 本来就只接受曝光后的输入**（帧缓冲 1.0 = 100 nit），物理亮度在进入帧缓冲前就乘好了曝光。
   本引擎把曝光移到 HDR 写入端，正是回到这个约定；tonemap 只剩 `× 2.5` 的单位换算。
2. 可以选择让 HDR 缓冲直接存 **GT 帧缓冲单位**（曝光值 × 2.5），tonemap 就与参考实现的输入完全
   同义。代价是 TAA、bloom 的 Karis 权重和直方图里的 "曝光后亮度" 都要换算一次常数。
   保持"曝光后 1.0 = 饱和"改动最少，这是设计时要拍板的一点。
3. 预曝光之后，太阳盘（1e9 nit）在日光 EV 15 下约为 2.5e4，落在 fp16 范围内，
   **bloom 和眩光终于能看到真实的超白能量**，这是做第 3 节那种物理眩光的前提。

### 后续候选（按与现有代码的距离排序）

1. **预曝光 HDR 缓冲**：已完成（2026-09-24）。
2. **眩光强度随曝光变化**（已完成，2026-09-25，含 HDR 下变窄）：用 EV 近似 F 值，调 bloom 的强度和各级权重，亮场景眩光强、暗场景弱。
3. **自动曝光的长期适应层与多参考测光**（已完成，2026-09-25）：天空和太阳照度已由大气系统在 CPU 侧给出，
   可以直接作为参考加入，天空可见度可以借用 VBAO 或 SH。
4. **HDR 显示输出**（已完成，2026-09-25，HDR10）：`initializeAsHDR(peak)` + PQ，需要 HDR10 交换链（HDR10 swapchain）和显示器峰值设置。
5. **色调映射烘焙成 3D LUT**（32³，x⁴ 索引）：评估后不采用。2026-09-25 在 CPU 上用同一份着色器代码做原型，三线性插值对比解析算子（20 万个随机颜色，8 位 sRGB）：32³、输入 0–64 帧缓冲单位时 8.6% 的通道差超过 1 级、最大差 42 级；64³、输入 0–256 时仍有 1.3% 超过 1 级、最大差 10 级，误差集中在色度褪色区和高饱和色。解析算子精确且每像素只有几十次 `pow`，按画面验收时 LUT 只会变差。
6. **自动白平衡**（已完成，2026-09-25）：依赖多参考测光，放在 3 之后。
7. **光追镜面 GI**：沿用 split-sum，替换预滤波 cubemap 项；依赖 RT 混合管线（见
   `docs/superpowers/specs/2026-09-04-raytracing-hybrid-pipeline-design.md`）。
