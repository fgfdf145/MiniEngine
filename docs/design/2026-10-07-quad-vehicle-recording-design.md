# 四机位车身姿态录制

日期：2026-10-07

## 目标

驾驶时从车的前、后、左、右四个方向同时拍摄，用来对比车身姿态（侧倾、俯仰、点头、蹲尾）。

- 四台相机各自可以设置分辨率、位置、注视点和视场角，都跟着车走。
- 边拍边合成：每一帧四台相机在同一时刻渲染，GPU 直接把四张图拼进一张画布，编码线程把画布写进一个视频文件，录完不需要再后期处理。
- 默认 2x2 网格：前（左上）、后（右上）、左（左下）、右（右下）。也可以选十字布局：前在上，左右在中间两侧，后在下，与车的方位一一对应。每个画面左上角写上机位名。

## 相机怎么跟车

相机的位置和注视点都在车的坐标系里给出（米：向右、向上、向前，与 Vehicle 面板的座位偏移相同）。车的姿态取 `VehicleDriveStatus::pose`，即画面上车身所在的插值姿态。

- 默认“只跟航向”：相机的原点跟着车身位置走，朝向只跟着车的航向（车头方向投影到水平面）转，不跟侧倾和俯仰。这样地平线保持水平，车身的侧倾和俯仰在画面里能直接看出来。这是对比车身姿态的关键：如果相机钉在车身上，车身在画面里永远是静止的。
- 可以对单台相机勾选“随车身倾斜”，此时相机固定在车身上，和车一起侧倾、俯仰。

没有在驾驶时，相机跟随当前选中的实体（静止的车也能先摆机位、看预览）；两者都没有时，四个视图不渲染，也不能开始录制。

默认机位：四台相机离车中心 6 米，高 0.8 米，看向车中心上方 0.6 米，垂直视场角 35 度，分辨率 960x540，拼成 1920x1080。

## 渲染器：一帧画多台相机

渲染器原来只有一个视图：所有目标、pass、帧描述符集和历史（TAA、AO、GI、SSR、运动向量、曝光）都是渲染器的成员。现在把这些拆进 `VulkanSceneView`，视口是其中一个，四台录制相机各一个。

每个视图自己的：

| 资源 | 原因 |
|---|---|
| `SceneRenderTargets` 和全部 scene pass | 尺寸不同；pass 自己持有历史图像 |
| G-buffer 描述符、`VulkanUniformBuffer`（set 0） | 相机常量、运动向量、光源分簇都随相机变；set 0 绑的 scatter 图像、云图、大气透视图、阴影图是每个视图自己的 |
| 级联阴影 `VulkanShadowPass` | 级联按相机视锥划分，缓存（ShadowCascadeCache）按视图记 |
| 大气的 aerial perspective 体积和体积云目标 | AP 体积沿相机视锥分布；云按像素行进并做时域重建 |
| 卡通材质缓冲（toon） | CPU 每帧按视图的绘制列表写入 |
| 布局跟踪、时域历史、TAA 抖动序号、自动曝光状态 | 每台相机自己适应、自己累积 |

所有视图共用的（每帧只做一次）：上传和内容提交、光源选择、模型矩阵、射线场景和 DDGI（以视口相机为中心）、蒙皮、局部光阴影图集、天空视图 LUT、云阴影、环境探针、白平衡、透射拷贝图像（每个视图的拷贝 pass 用之前重写它）、材质管线（各视图的 render pass 格式相同，彼此兼容）。

录制视图不做的：DLSS（用引擎自己的 TAA）、路径追踪 / ReSTIR PT（视口开着时录制视图退回光栅化 + 光追效果）、选中描边、GPU 分 pass 计时（每个视图只记一个总时间）。

命令缓冲里的顺序：蒙皮 → 局部阴影 → 大气共用部分 → 环境探针 → 射线场景 → DDGI → 每个录制视图（阴影、AP、云、scene pass、把 `SceneLdr` 复制进画布）→ 视口（同上）→ ImGui → 视口录像的回读。

## 画布与编码

`ComputeVideoMosaicLayout` 根据四台相机的尺寸算画布和每格位置：2x2 网格的列宽取该列最大宽度，行高取该行最大高度，画面在格子里居中；十字布局是 3x3。画布宽高向上取偶数（H.264 4:2:0 需要）。

`VulkanVideoReadback::RecordMosaicCopy` 先用 `vkCmdFillBuffer` 把回读缓冲清成黑色，再对每个视图做一次 `vkCmdCopyImageToBuffer`，`bufferOffset` 指到格子左上角，`bufferRowLength` 是画布宽度，所以四张图直接落在画布对应位置，CPU 不做拷贝。回读后在 CPU 上用内置 5x7 点阵字写机位名，交给一个独立的 `VideoRecorder`（与 Tools > Record Viewport 互不影响，可以同时录）。

节奏与视口录像相同：实时录制按真实时间（编码跟不上时丢帧，重复帧补齐）；`--frames` 脚本运行每帧一格。

## 界面与命令行

- Window > Quad Recording：四个机位的分辨率（预设 + 自定义）、位置、注视点、视场角、是否随车身倾斜；布局、帧率、是否写机位名；实时预览（按最终画面的布局排列）；开始 / 停止按钮和录制状态。设置保存在 `miniengine.settings.json` 的 `quad_recording` 里。
- Tools > Record Quad Cameras（Ctrl+Shift+F12）开始或停止，文件写到 `captures/quad_<日期>_<时间>.mp4`。
- 命令行：`--quad-record <path>` 在场景就绪后开始录制，退出时结束；配合 `--drive`、`--drive-controls`、`--frames` 可以无人值守地录一段测试。

## 代价

每台录制相机是一整套场景渲染。960x540 的四台相机加起来像素数约等于一个 1080p 视口，GPU 时间大致翻倍；显存每个视图约 100 MB（目标）+ 64 MB（2048² x 4 级联阴影）。分辨率越高代价越大，界面上显示画布尺寸。

## 测试

- 单元测试：机位计算（只跟航向时地平线水平、随车身时与车身一致、位置和注视点的坐标系）、拼图布局（网格 / 十字、不同尺寸居中、偶数画布）、点阵字写入。
- 运行测试：`--drive` + `--drive-controls` 让 R34 转弯，`--quad-record` 录 300 帧，抽帧检查四个画面的内容与方向，以及视口画面与改动前一致。
