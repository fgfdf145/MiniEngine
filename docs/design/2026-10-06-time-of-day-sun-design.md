# 时间驱动的太阳（北半球轨迹）

日期：2026-10-06

## 目标

场景新增“时间”：给定一年中的第几天、当地太阳时和纬度，太阳（场景里的方向光）沿北半球的真实轨迹移动——东升、正午过正南、西落；光线的颜色和强度随太阳高度变化，低空变红，落到地平线下熄灭。

## 设置（`TimeOfDaySettings`，`SceneEnvironment::timeOfDay`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | false（旧场景）；新场景 true | 关闭时太阳保持手动旋转 |
| `hours` | 14.0 | 当地太阳时，[0, 24)，12 点太阳在正南最高 |
| `dayOfYear` | 279（10 月初） | 1..365 |
| `latitudeDegrees` | 35.7（东京） | 钳制到 [0, 90]：轨迹永远是北半球的 |
| `northDegrees` | 0 | 世界里北的方向：0 时北 = -Z、东 = +X、南 = +Z（默认相机身后）；正值绕 +Y 旋转 |
| `timeScale` | 0 | 每真实秒推进的场景秒数，0 = 时间静止；3600 = 一秒一小时 |

YAML 键：`environment.time_of_day.{enabled, hours, day_of_year, latitude_degrees, north_degrees, time_scale}`。没有该节点的旧场景读成关闭，太阳位置不变。

默认值选成 14:00 / 10 月初 / 东京：太阳高度约 40°、方位约 220°（西南），接近原来手摆的“35° 高、正南、在默认相机身后”。

## 太阳位置（`engine/scene/sun_position.h`）

- 赤纬：圆轨道黄经 λ☉ = 2π (N − 80) / 365（第 80 天春分），δ = asin(sin ε sin λ☉)，ε = 23.44°。（最初用 Cooper 余弦拟合，加月亮时换成黄道坐标，让日月用同一套。）
- 时角 H = 15° · (hours − 12)。
- 东-北-天坐标中的太阳方向（球形地球，不含大气折射与时差方程）：
  - E = −cos δ sin H
  - N = cos φ sin δ − sin φ cos δ cos H
  - U = sin φ sin δ + cos φ cos δ cos H
- 世界坐标：东轴 = R_y(north)·(+X)，北轴 = R_y(north)·(−Z)，天 = +Y。
- 方向光的欧拉角（XYZ，与 `BuildLightRotation` 一致，光沿局部 −Y 照射）：Rx(x)·Rz(z)·(0,−1,0) = (sin z, −cos z cos x, −cos z sin x)，解得 z = asin(d.x)，x = atan2(−d.z, −d.y)，y = 0。

“北半球钳制”就是纬度钳制到 [0, 90]：负纬度当作赤道。纬度 ≥ 23.44° 时正午太阳一定在正南；在热带（0–23.44°）夏季正午太阳可以在北边，这是北半球的真实情况，不做额外处理。

## 谁转动太阳

`EditorScene::ApplyTimeOfDay()`：时间开启时，把最亮的方向光（即渲染器用来照亮天空、投射阴影的那个）的 `rotationDegrees` 设成上面的欧拉角。调用点：

- `SetEnvironment`（面板修改、时间推进都走这里）；
- `ApplySceneData`（加载场景）；
- `AddDefaultSunAndSky`（新场景默认开启）。

时间开启时手动旋转太阳会在下一次时间变化时被覆盖。`timeScale > 0` 时 `EditorRenderBackendBase::TickSharedFrame` 每帧推进时钟（单帧最多计 0.25 s，卡顿不会让太阳跳过半个天空），在 24 h 处回绕。

## 光线（颜色/强度）

不在实体上改颜色/强度——光的强度仍是大气层顶的照度。渲染器已有的逻辑在 Atmosphere 模式下乘以相机高度处到太空的透射率（`ComputeTransmittanceToSpace`）：太阳低时变红变暗，地平线以下为 0。现在时间开启时，None / HDRI 模式也乘这个透射率（用场景的大气参数），所以没有画天空也一样会有日落和夜晚。天空、云、高度雾、环境探针都已经跟随太阳方向。

## 月亮与夜空（2026-10-06 追加）

用户要求“加个月光，夜里别全黑”。

新增字段（`time_of_day` 下）：`moon_enabled`（默认 true）、`moon_phase`（[0,1)，0 新月、0.25 上弦、0.5 满月、0.75 下弦，默认 0.5）、`moon_brightness`（倍率，默认 1）、`night_sky_luminance`（cd/m²，默认 0.01）。

**月亮位置**：月亮放在黄道上（忽略 5° 轨道倾角），黄经 λ☾ = λ☉ + 2π·phase。赤纬、赤经按黄道→赤道换算；时角 H☾ = H☉ + α☉ − α☾（恒星时由太阳时角和太阳赤经确定）。所以满月正好在太阳对面（日落时东升、整夜都在），新月和太阳重合，上弦在日落时位于正南。

**月光强度**：满月在大气层外 0.267 lux（视星等 −12.74），乘以 Allen 的相位角经验式 10^(−0.4 (0.026 α + 4×10⁻⁹ α⁴))（α 为相位角：满月 0°，新月 180°；上下弦约 9%，新月约 0.03%），再乘 `moon_brightness`。颜色 `kMoonlightColor` 偏蓝（暗视觉的 Purkinje 偏移，也是大家记忆和绘画里的夜色）。

**接管方式**：不新增灯光实体。太阳高度低于 `kMoonTakesOverSunElevationDegrees` 时，渲染器在选出太阳光之后、构建阴影之前，把那盏光的方向和照度换成月亮的（`ComputeMoonlight`）。后面所有用到“太阳”的地方——阴影、大气天空（月光的瑞利散射给出暗蓝夜空）、太阳圆盘（变成月亮圆盘，角直径相近）、云、高度雾、曝光参考——都自动换成月亮。场景文件和编辑器里的灯光实体仍是太阳。

**交接阈值 −11°**：在 R34 测试场景（10 月初、北纬 35.7°、朝南看）上测量。曝光此时都在 EV100 下限 −2，用 8 位画面平均亮度比较：只用太阳时，−8° 为 59.5，−10° 为 48.9，−12° 为 13.1，−14° 为 0.4；满月（此时在地平线上 10–12°）约 20。最初定的 −8° 会从 59 掉到 17，跳变明显；改成 −11° 后，在 18:35 / 18:37 两侧实测为 45.7 → 38.6（加夜空光之后），约 0.25 档。

**夜空光（`nightSky`）**：只有月亮时，上弦之后和新月夜仍是全黑（实测平均 3.7 和 0）。因此加了一项夜空自身的亮度（气辉加星光），在 `SampleSkyViewLut` 里对地平线以上的方向加 `ubo.nightSky.rgb`，于是天空背景、天空 SH 环境光、环境探针反射、云的环境光都能拿到。环境 uniform 新增一个 vec4（25 → 26 个），只在时间开启时非零。真实无月夜空约 0.0002 cd/m²；曝光下限是 EV100 −2，达不到人眼的暗适应，所以默认值提高到 0.01，相当于暗适应后的观感。颜色 `kNightSkyColor` 按 Rec.709 亮度归一。白天天空是几千 cd/m²，这一项可以忽略（14:00 的 EV100 前后都是 16.23）。

加夜空光后实测平均亮度：满月午夜 58.7，上弦 21:00 为 26.4，新月午夜 22.7，白天 14:00 为 63.8。

## 已知限制

- 太阳时而非钟表时间（无经度/时区/时差方程，误差最多约 ±16 分钟）。
- 时间推进时环境探针每帧重新捕获（与手动旋转太阳相同的已有行为）。
- 月相是手动设置的，不会随日期推算（没有年份），时间走一整天月相也不变；月亮圆盘不画盈亏形状；没有星星。
- 月亮接管的阈值是固定的 −11°，按满月调的。其他月相下，交接时画面会变暗一点。
