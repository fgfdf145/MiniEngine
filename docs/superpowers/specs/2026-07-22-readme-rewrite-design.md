## README 结构

### 1. 项目定位

- 用一句话说明 MiniEngine 是基于 SDL3、Vulkan、Dear ImGui 与 EnTT 的 3D 场景编辑器原型。
- 明确当前已形成编辑器工作流闭环，但尚无完整游戏运行时闭环。
- 给出 C++20、CMake、vcpkg 以及当前真实依赖；移除未使用的 `nlohmann-json`。

### 2. 功能总览

按用户可感知的工作流归类，而不是按源码文件罗列：

- 编辑器与视口交互。
- 场景实体、灯光、变换和 YAML 持久化。
- 资产浏览、批量操作、导入和稳定 UUID。
- glTF 2.0 模型处理、材质 sidecar 与材质图编辑。
- Vulkan PBR 渲染、多类型灯光、贴图与视口渲染。
- 异步模型加载、异步场景加载和后台资产导入。
- 编辑器设置、主题、输入监视及跨桌面平台构建入口。

### 3. 架构与数据流

- 列出真实的 CMake 目标依赖方向。
- 解释 `app -> application -> renderer/editor -> logic/scene/asset -> platform/core` 的职责边界。
- 用简短步骤说明启动链路和逐帧链路。
- 明确当前 RHI 只有 Vulkan 实现，且 Vulkan 后端仍继承编辑器后端基类，这是已知边界而非完整多后端架构。
- 区分稳定编辑器顺序、EnTT 运行时查询、CPU Renderable 增量更新和 Vulkan GPU 资源整批上传。

### 4. 仓库结构

根据当前目录和 CMake 目标说明 `app/`、`engine/*`、`assets/`、`shaders/`、`tests/`、`scripts/`、`cmake/`、`docs/` 与设置文件的用途。

目录说明只覆盖对维护有帮助的层级，不把 README 写成逐文件 API 索引。

### 5. 数据、资源与实现约定

保留并压缩现有硬性规则：

- Vulkan UV 方向和贴图不翻转。
- 世界单位为米。

- `ISceneWorld::Registry()` 对外只读，场景变更走受控接口。
- CMake 目标依赖不可反转，根 `.slnx` 只是 CMake 的 IDE 包装层。

### 6. 构建、运行与验证

- 列出 C++20、CMake、Vulkan 工具链与 vcpkg 前提。
- Windows 首选 Visual Studio 2026 preset 和根 `MiniEngine.slnx`。
- 保留 PowerShell bootstrap/build/generate-sln 用法。
- 列出 macOS 与 Linux presets，但不扩大其已验证范围。
- 说明 `--backend vulkan`、`--model` 与 `--frames`。
- 给出 CTest 和 60 帧冒烟测试命令，并说明文档修改只做静态检查，不以此冒充运行验证。

### 7. 当前能力边界

明确记录当前代码尚未覆盖的能力：

- 只有 Vulkan 后端。
- glTF 的额外 UV 集、sampler wrap 与 `KHR_texture_transform` 尚未完整处理。
- 启动默认配置和部分场景引用刷新仍以路径为主。
- CPU Renderable 可按实体刷新，但 Vulkan GPU 资源集合仍整批上传。
- 脚本、动画、物理、音频、Play 模式和完整运行时分层尚未实现。
