# Bloom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Energy-conserving bloom (Jimenez 2014) after TAA, composited in place into `SceneTaa`; off = today's image.

**Architecture:** A pure `BuildBloomMipChain`; a compute pass `VulkanBloomPass` owning a mip-chained RGBA16F image, running downsample, upsample and composite dispatches of `bloom.comp` with memory barriers between them; `ScenePassId::Bloom` after `Taa` in both orders.

**Tech Stack:** C++20, Vulkan compute, GLSL 450, CTest executables.

**Spec:** `docs/superpowers/specs/2026-09-24-bloom-design.md`

## Global Constraints

- Up to 6 levels from half resolution; stop before a side < 2.
- 13-tap downsample (Karis average on the first), 3x3 tent upsample, `mix(scene, bloom / levels, intensity)`.
- Default on, intensity 0.04, slider 0-0.2.

## Review Focus

- Tiny viewports (the editor can shrink the viewport to a few pixels): the chain must stay valid.
- The sun disk (65504) must not make NaN/inf or a flickering blob (Karis average, sanitising).
- Bloom off records nothing: `SceneTaa` untouched.
- Barriers: every dispatch reads what the previous one wrote; the next frame discards the chain.
- Resize: the chain is recreated with the targets and its descriptor sets rewritten.
